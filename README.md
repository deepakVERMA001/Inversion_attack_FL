# Gradient Inversion Attacks in Federated Learning

## Overview

This project demonstrates how gradients shared during Federated Learning can leak information about a client's private training data.

In Federated Learning, clients train a machine learning model locally and send gradients or model updates to a central server instead of sending their raw data.

However, gradients may still contain information about the original training samples.

This project demonstrates two types of Gradient Inversion Attacks:

1. Optimization-Based Gradient Inversion Attack
2. Analytics-Based Gradient Inversion Attack

The experiments are performed using the **CIFAR-10 dataset** and a simple convolutional neural network.

## Dataset

The project uses the **CIFAR-10 dataset**.

CIFAR-10 contains 60,000 color images belonging to 10 different classes.

Each image has the size: 32 × 32 × 3

The 10 classes are:
Airplane
Automobile
Bird
Cat
Deer
Dog
Frog
Horse

Truck


# 1. Optimization-Based Gradient Inversion Attack

## Description

In an Optimization-Based Gradient Inversion Attack, the attacker receives or obtains the gradient generated from a client's private training sample.

The attacker does not have access to the original image.

Instead, the attacker starts with a randomly generated dummy image.

The dummy image is passed through the same neural network, and a dummy gradient is calculated.

The attacker then compares the dummy gradient with the leaked gradient.

The dummy image is repeatedly updated so that its gradient becomes increasingly similar to the leaked gradient.

After several optimization iterations, the dummy image may begin to resemble the original private image.

## Gradient Matching

The attacker tries to minimize the difference between the leaked gradient and the gradient generated by the dummy image.

In this implementation, cosine distance is used to measure the similarity between the real gradient and the dummy gradient.

The optimization process can be represented as:

Leaked Gradient
        |
        | Compare
        v
Dummy Gradient
        |
        v
Gradient Matching Loss
        |
        v
Update Dummy Image


The important point is that the dummy gradient is not generated randomly.

It is calculated from the current dummy image using the same model.

The optimization therefore updates the dummy image rather than directly modifying the dummy gradient.


## Experiment Procedure

The following steps are performed:

1. Load an image from the CIFAR-10 dataset.
2. Pass the image through a simple convolutional neural network.
3. Calculate the prediction.
4. Calculate the loss.
5. Perform backpropagation.
6. Save the generated gradient.
7. Treat the saved gradient as a simulated leaked client gradient.
8. Generate a random dummy image.
9. Pass the dummy image through the same model.
10. Calculate its gradient.
11. Compare the dummy gradient with the leaked gradient using cosine distance.
12. Optimize the dummy image.
13. Repeat the process for multiple iterations.
14. Observe whether the dummy image gradually becomes similar to the original image.

# 2. Analytics-Based Gradient Inversion Attack

## Description

Analytics-Based Gradient Inversion Attack reconstructs private input data using a mathematical relationship between the input and the gradients of a linear layer.

Unlike the optimization-based attack, this approach does not require repeatedly optimizing a dummy image.

Consider a linear layer:


z = Wx + b
where:
x = input
W = weight
b = bias
z = output of the linear layer before activation

During backpropagation, the gradient with respect to the weight is:
Gradient of W = delta × x
and the gradient with respect to the bias is:
Gradient of b = delta
Therefore:

Gradient of W
---------------- = x
Gradient of b

or mathematically:
x = Weight Gradient / Bias Gradient
The unknown backpropagation term cancels during division.

## Important Condition

Exact reconstruction using this simple equation is possible when a single training sample contributes to the corresponding neuron.
If multiple samples contribute to the same neuron, the weight gradient becomes a combination of multiple inputs.
For example:
Gradient = Image 1 contribution
         + Image 2 contribution
         + Image 3 contribution

In this case, directly dividing the weight gradient by the bias gradient may produce a mixture instead of one exact image.
More advanced analytical attacks such as **Robbing-the-Fed** try to overcome this problem by modifying the model so that individual samples can be isolated into different neurons or bins.

# Purpose of the Project

The main purpose of this project is to demonstrate that keeping raw training data on the client device does not automatically guarantee complete privacy in Federated Learning.

Even when the original images are not directly shared, gradients generated during training may contain information about the client's private data.

The project helps study:

- privacy risks in Federated Learning;
- gradient leakage;
- optimization-based gradient reconstruction;
- analytical gradient reconstruction;
- limitations of gradient sharing;
- the need for privacy-preserving defenses.

# Note

The leaked gradient used in this project is simulated by calculating and saving the gradient generated from a CIFAR-10 training sample.

In an actual Federated Learning system, the attacker may attempt to observe or exploit gradients or model updates exchanged between clients and the federated server.

This project is intended for educational and research purposes to study privacy vulnerabilities and possible defensive mechanisms in Federated Learning.
